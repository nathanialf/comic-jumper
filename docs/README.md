# docs/

An index of this directory: what each file is for.

| file | what it is |
| --- | --- |
| [`BUILDING.md`](BUILDING.md) | the full build: host packages, what `./build.sh`, `tools/setup.sh` and each step do, the hooks, the dashboard |
| [`LEGAL.md`](LEGAL.md) | what the repository may and may not contain, which references were used, and why the XEX2 retail key is in a tool. Read it before contributing |
| [`TARGETS.md`](TARGETS.md) | the target and what its executable says about its own build |
| [`DECISIONS.md`](DECISIONS.md) | the evidence standard and every decision made under it; D1, the compiler, is open |
| [`MATCH.md`](MATCH.md) | the matching method: the loop, what counts as a hypothesis, structure over count, crutches, evidence discipline; its compile and compare steps wait on D1 |
| [`FINISHING.md`](FINISHING.md) | the end state: the standing rules and tickets F1 to F15 that turn a matched tree into the developer's tree, and the release |
| [`SURVEY.md`](SURVEY.md) | the executable's map: container fields, sections, function counts, imports, libraries, the source directories it names. Generated by `tools/survey_pe.py --md` |
| [`retail/`](retail/) | the target's progress files: `PROGRESS.md` and `progress.json`, its data. Generated by `tools/check_pe.py --progress` |
| `index.html` | the progress dashboard, which reads `retail/progress.json`; `.github/scripts/build_pages_site.sh` publishes it with `retail/progress.json` and `retail/PROGRESS.md` to GitHub Pages, and nothing else from this directory |

`tools/README.md` describes every tool.

## Local files that are not part of the repository

A maintainer's checkout may also hold `NOTES.md` and `COOKBOOK.md` here:
notes on the compiler's behaviour and parked functions. They are gitignored,
nothing in the build reads them, and nothing in the repository depends on
them.
